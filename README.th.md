# OrkasVideoStudio

> OrkasVideoStudio คือโปรแกรมตัดต่อวิดีโอ AI แบบโอเพนซอร์สที่เปลี่ยนเอเจนต์เขียนโค้ดของคุณให้เป็นสตูดิโอวิดีโอ ขอวิดีโอที่เสร็จสมบูรณ์จาก Claude Code, Codex, Cursor หรือเอเจนต์ใดก็ได้ที่รันเชลล์หรือรองรับ MCP ได้ เอเจนต์จะตัดต่อฟุตเทจของคุณ ออกแบบโมชันกราฟิก ใส่เสียงบรรยาย เพลง และคำบรรยายใต้ภาพ สร้างช็อตที่ขาดด้วยคีย์ของคุณเอง แล้วส่งมอบไฟล์ MP4 ที่ผ่านการตรวจสอบแล้ว คุณยังแก้ไข MP4 นั้นต่อบนแคนวาสในเบราว์เซอร์ได้

**ทางเลือกโอเพนซอร์สแทน Claude Motion, CapCut และ Higgsfield ที่สั่งงานด้วยเอเจนต์เขียนโค้ดที่คุณใช้อยู่แล้ว** ใช้สัญญาอนุญาต MIT และให้ความสำคัญกับการทำงานภายในเครื่อง ไม่ต้องใช้แผน Claude Team หรือ Enterprise และไม่ต้องสมัครสมาชิกแพลตฟอร์มวิดีโอใด ๆ ช็อตที่สร้างขึ้นมาจาก Seedance, Kling, Veo และโมเดลวิดีโออื่น ๆ ผ่านคีย์ของคุณเอง [เปรียบเทียบกับเครื่องมืออื่น ↓](#เปรียบเทียบกับเครื่องมืออื่น)

**อยากใช้แอปมากกว่าเอเจนต์เขียนโค้ดใช่ไหม?** OrkasVideoStudio ยังเป็นเอเจนต์วิดีโอในตัวของ **[Orkas](https://orkas.ai/?source=gh-orkas-vs)** แอปเดสก์ท็อปทีม AI ฟรีสำหรับ macOS และ Windows ด้วย อธิบายวิดีโอที่ต้องการในแชต แล้วการสร้างสื่อจะทำงานบนโมเดลในตัวของ Orkas (บัญชีใหม่รับฟรี 500 เครดิต) หรือบนคีย์ของคุณเอง **[ดาวน์โหลด Orkas →](https://orkas.ai/download/?source=gh-orkas-vs)** · [ทั้งสองเกี่ยวข้องกันอย่างไร ↓](#ความสัมพันธ์กับ-orkas)

*วิดีโอภาพรวมความยาว 54 วินาทีด้านบนแสดงให้เห็นว่าบรีฟเดียวกลายเป็นวิดีโอที่เสร็จสมบูรณ์ได้อย่างไร ตั้งแต่การตัดต่อฟุตเทจจริง การออกแบบโมชัน การใส่เสียงพูด เพลง และคำบรรยายใต้ภาพ การลองดูช็อตต่าง ๆ บนแคนวาส ไปจนถึงการเปลี่ยนคำ สลับช็อต หรือเรียงลำดับฉากใหม่*

OrkasVideoStudio **ไม่ใช่เอเจนต์วิดีโอแบบกล่องดำ** เอเจนต์ของคุณเป็นผู้คิดเอง โปรเจกต์นี้มอบส่วนประกอบที่เอเจนต์ด้นสดขึ้นเองไม่ได้ให้:

- **ความรู้ด้านวิดีโอ** ชุด `SKILL.md` ที่ไม่ผูกกับโฮสต์ใด โดยมี `video-studio` เป็นทักษะตั้งต้น ครอบคลุมว่าเมื่อไรควรถามและเมื่อไรควรทำต่อ โฆษณา วิดีโออธิบาย เดโมสินค้า วิดีโอตัดต่อตามเพลง วิดีโอที่มีผู้นำเสนอ หนังสั้น และวิดีโอเล่าและวิจารณ์ต่างกันอย่างไร และต้องตรวจคัตอย่างไรก่อนจะถือว่าเสร็จ
- **เครื่องมือที่ให้ผลแน่นอน (deterministic)** CLI `ovs` และเซิร์ฟเวอร์ MCP ที่มีคำสั่งตรงกับ CLI ครอบคลุมไทม์ไลน์ของโปรดักชัน การตัดต่อด้วย ffmpeg การถอดเสียงเป็นข้อความ การวิเคราะห์ฟุตเทจ และการสร้างสื่อผ่านบัญชีผู้ให้บริการของคุณเอง [HyperFrames](https://github.com/heygen-com/hyperframes) ทำหน้าที่เรนเดอร์หน้าเพจและจับภาพเฟรม ส่วน `ffmpeg` ทำหน้าที่ตัดต่อและวัดค่า
- **โปรดักชันที่แก้ไขได้** วิดีโอแต่ละชิ้นเป็นโฟลเดอร์ธรรมดา ประกอบด้วยไทม์ไลน์ฉาก (`videos/main/manifest.json`) บัญชีรายการแอสเซ็ต ข้อเท็จจริงของสินค้าที่ระบุแหล่งที่มา และหน้าเพจที่ออกแบบไว้ (ไม่บังคับ) ทั้งคุณ เอเจนต์ของคุณ และแคนวาสในเบราว์เซอร์แก้ไขไฟล์ชุดเดียวกัน เปลี่ยนข้อความหนึ่งบรรทัด สลับรูปภาพ หรือเรียงลำดับฉากใหม่ แล้วเรนเดอร์อีกครั้ง

การตัดต่อ โมชันกราฟิกที่ออกแบบไว้ คำบรรยายใต้ภาพ และการถอดเสียงเป็นข้อความ **ไม่ต้องใช้คีย์ API** การสร้างภาพ วิดีโอ และเสียงพูดเป็นตัวเลือกที่ต้องเปิดใช้เอง และใช้บัญชีผู้ให้บริการ **ของคุณเอง** ไม่มีแบ็กเอนด์ที่โฮสต์ไว้ และไม่ต้องสร้างบัญชีใด ๆ

## สิ่งที่คุณขอได้

คุณขอเพียงครั้งเดียวและได้วิดีโอที่เสร็จสมบูรณ์หนึ่งชิ้น เอเจนต์จะรวมทุกอย่างที่คำขอต้องการไว้ในไทม์ไลน์เดียว:

| ความสามารถ | ครอบคลุมอะไรบ้าง |
|---|---|
| **ตัดต่อฟุตเทจจริง** | ตัดช่วง ต่อคลิป ปรับเฟรมเป็น 9:16 / 1:1 / 16:9 คงหรือมิกซ์เสียงของคลิป ซ้อนภาพ ฝังซับไตเติล และปรับความดังเสียงให้สม่ำเสมอ สำหรับวิดีโอที่บันทึกไว้ยาว ๆ ยังหาช่วงไฮไลต์ จัดอันดับเทคที่ถ่ายซ้ำ และตัดช่วงเงียบหรือคำเติมออกได้ด้วย พร้อมบันทึกหลักฐานของการตัดแต่ละจุด |
| **โมชันที่ออกแบบไว้** | ฉากที่สร้างด้วย HTML/CSS พร้อมแอนิเมชัน: ตัวอักษรเคลื่อนไหว (kinetic type) การ์ดราคา แถบข้อความด้านล่าง (lower-third) ป้ายเน้นข้อมูล และทรานซิชัน คำที่แก้ไขได้อยู่ในช่องข้อความที่มีชื่อกำกับ การเปลี่ยนข้อความจึงไม่ต้องสร้างฉากใหม่เลย |
| **เสียงและคำบรรยายใต้ภาพ** | เสียงบรรยายของแต่ละฉากที่ปรับให้พอดีกับความยาวของฉากนั้น เพลงประกอบที่มีสิทธิ์ใช้งานซึ่งจะลดเสียงลงเมื่อมีเสียงพูด คำบรรยายใต้ภาพจากข้อความบรรยายหรือจากจังหวะเวลาของคำที่วัดได้ การตัดที่ตรงกับจังหวะบีต |
| **ช็อตที่สร้างขึ้น** | ภาพ คลิปวิดีโอ และผู้นำเสนอที่สร้างขึ้น (แบบพูดหน้ากล้อง) จากผู้ให้บริการที่คุณตั้งค่าไว้ สำหรับช็อตที่สื่อของคุณแสดงไม่ได้ และจะสร้างภายในวงเงินที่คุณอนุมัติเท่านั้น |

สำหรับสคริปต์หรือสตอรีบอร์ด เอเจนต์จะหยุดที่เอกสาร สำหรับวิดีโอที่เสร็จสมบูรณ์ เอเจนต์จะทำต่อจนถึงการส่งมอบ เอเจนต์จะแสดงแผนหรือพรีวิวให้ดูเฉพาะเมื่อคุณขอ หรือเมื่อวิดีโอยาวเกินประมาณสองนาที สคริปต์ที่เอเจนต์เขียนขึ้นให้วิดีโอพูดตามคำต่อคำจะแสดงให้คุณดูก่อน ส่วนสคริปต์ที่คุณให้มาจะทำตามที่เขียนไว้

## โมชันกราฟิกใน Claude Code โดยไม่ต้องใช้แผน Team

Claude Motion ฟีเจอร์แอนิเมชันของ Anthropic เปิดให้ใช้แบบเบต้าเฉพาะในแผน Claude Team และ Enterprise เท่านั้น OrkasVideoStudio ทำให้ Claude Code สร้างโมชันกราฟิกที่เขียนด้วยโค้ดแบบเดียวกันได้บน Pro, Max, Ultra หรือคีย์ API: เอเจนต์จะเขียนแต่ละฉากเป็น HTML และ CSS พร้อมแอนิเมชัน ตรวจดูเฟรมตัวอย่าง และเรนเดอร์ MP4 บนเครื่องของคุณ ตัวการเรนเดอร์จึงไม่ใช้โทเคนเลย

1. [ติดตั้ง](#การติดตั้ง) OrkasVideoStudio แล้วรัน `ovs skills --install --target claude` (หรือ `--target codex` สำหรับ Codex)
2. ขอวิดีโอ เช่น *"ทำวิดีโอโมชันกราฟิก 16:9 ยาว 20 วินาทีสำหรับเปิดตัวแอปของเรา: ฉากเปิดแบบตัวอักษรเคลื่อนไหวที่แสดงชื่อผลิตภัณฑ์ การ์ดฟีเจอร์สามใบที่สไลด์เข้ามา และการ์ดปิดท้ายที่แสดงราคา ขอดูภาพนิ่งของแต่ละฉากก่อนเรนเดอร์"*
3. เปลี่ยนคำ สี หรือจังหวะเวลาด้วยตัวเองในไฟล์ฉากหรือบนแคนวาส หรือขอให้เอเจนต์ทำ แล้วเรนเดอร์อีกครั้ง

ต่างจาก Claude Motion ตรงที่ไทม์ไลน์เดียวกันยังรวมฟุตเทจ เสียงบรรยาย เพลง และคำบรรยายใต้ภาพของคุณเองไว้ได้ด้วย ดู[การเปรียบเทียบ](#เปรียบเทียบกับเครื่องมืออื่น)

### สร้างวิดีโอยอดนิยมขึ้นใหม่

|---|---|
| *"สร้างโครงสร้างและจังหวะของวิดีโอไวรัลนี้ขึ้นใหม่สำหรับสินค้าของฉัน ขอดูแผนก่อน"* | แยกองค์ประกอบของวิดีโอต้นแบบ จับคู่จังหวะเรื่องของต้นแบบเข้ากับสื่อของคุณ และรอให้คุณอนุมัติก่อนเริ่มผลิต |
| *"โฆษณาของคู่แข่งตัวนี้ได้ผลดี ทำของเราด้วยฮุกและจังหวะแบบเดียวกัน โดยใช้รูปของเรา"* | ยืมจังหวะของฮุก การพิสูจน์ และคำกระตุ้นให้ลงมือทำจากต้นแบบ แต่ไม่ยืมเนื้อหา ทุกคำกล่าวอ้างมาจากข้อเท็จจริงของสินค้าคุณ และทุกภาพมาจากสื่อของคุณ |

ส่ง **ไฟล์วิดีโอต้นแบบ** ให้เอเจนต์ของคุณ พร้อมแอสเซ็ตสินค้า สคริปต์ หรือฟุตเทจของคุณเอง เอเจนต์จะใช้ OrkasVideoStudio สร้าง **โครงเรื่อง สไตล์ภาพ และจังหวะการตัดต่อ** ของต้นแบบขึ้นใหม่สำหรับเนื้อหาใหม่ได้:

1. **วิเคราะห์ต้นแบบ** ตรวจดูเฟรมตัวอย่างและเสียงที่เกี่ยวข้อง เพื่อระบุฮุก ช่วงสาธิตหรือการพิสูจน์ ลำดับข้อมูล การจัดตัวอักษร ทรานซิชัน จังหวะ และคำกระตุ้นให้ลงมือทำ
2. **วางแผนการดัดแปลง** ระบุว่าจะคงอะไรไว้และจะแทนที่อะไร แล้วจับคู่ช่วงต่าง ๆ ของต้นแบบกับฉากใหม่หรือไทม์ไลน์ ปรับจังหวะเวลาให้เข้ากับเสียงบรรยายและเวลาในการอ่านจริงของคุณ
3. **ผลิตและแก้ไข** จัดองค์ประกอบโมชันกราฟิก ตัดต่อฟุตเทจของคุณ และสร้างภาพที่ขาดเมื่อจำเป็น ข้อความ คำบรรยายใต้ภาพ เสียงบรรยาย และคลิปที่สร้างภายในเครื่องยังแก้ไขแยกกันได้ ส่วนข้อความที่ฝังอยู่ในฟุตเทจที่สร้างขึ้นจะเปลี่ยนได้ด้วยการเปลี่ยนฟุตเทจนั้นเท่านั้น

วิธีนี้เหมาะที่สุดกับวิดีโออธิบายแบบโมชันกราฟิก เดโม SaaS และแอป และโฆษณาสินค้าที่ทำจากฟุตเทจที่มีอยู่แล้ว เริ่มจากไฟล์ที่เอเจนต์ของคุณอ่านได้ เพราะไม่มีฟีเจอร์ดาวน์โหลดจากลิงก์แชร์ของแพลตฟอร์มโซเชียลในตัว ไม่รับประกันการเคลื่อนกล้องที่ตรงเป๊ะ การแสดงของคน หรือการจับคู่ทีละเฟรม การตรวจสอบก่อนส่งมอบไม่ได้ให้คะแนนว่าผลลัพธ์ใกล้เคียงต้นแบบแค่ไหน ดูรายละเอียดได้ที่[ขั้นตอนการสร้างวิดีโอใหม่ตามต้นแบบ](./packages/skills/video-craft/references/reference-recreation.md)

## การติดตั้ง

**สิ่งที่ต้องมี:** Node ≥ 22, `pnpm` และ `ffmpeg` + `ffprobe` ใน `PATH` ของคุณ แพ็กเกจ [HyperFrames](https://github.com/heygen-com/hyperframes) `0.7.60` ตามเวอร์ชันที่กำหนดไว้จะถูกติดตั้งเป็นดีเพนเดนซี และใช้เรนเดอร์หน้าเพจใน Chrome แบบ headless สำหรับการตรวจสอบและการเรนเดอร์ ส่วน `npx` เป็นเพียงทางสำรองเพื่อความเข้ากันได้ การสร้างสื่อเป็นตัวเลือกเสริมและต้องใช้คีย์ของคุณเอง

### จากซอร์สโค้ด

```bash
git clone https://github.com/Orkas-AI/Orkas-VideoStudio.git
cd Orkas-VideoStudio
pnpm install && pnpm build
alias ovs="node $PWD/packages/cli/dist/index.js"
ovs doctor          # checks Node, ffmpeg and ffprobe and explains how to install anything missing
```

แพ็กเกจ npm ยังไม่ได้เผยแพร่ ตอนนี้จึงให้ติดตั้งจากซอร์สโค้ดไปก่อน

## สั่งงานจาก Claude Code, Codex หรือเอเจนต์เขียนโค้ดตัวใดก็ได้

CLI `ovs` คืออินเทอร์เฟซหลัก และเครื่องมือ MCP มีคำสั่งตรงกับ CLI ใช้วิธีใดก็ได้ที่เอเจนต์ของคุณรองรับ:

**1) ทักษะแบบเนทีฟ (Claude Code / Codex)** ติดตั้งชุดทักษะเพื่อให้เอเจนต์ค้นพบได้เอง:

```bash
ovs skills --install --target claude   # → ~/.claude/skills  (add --scope repo for ./.claude/skills)
ovs skills --install --target codex    # → ~/.agents/skills  (add --scope repo for ./.agents/skills)
```

ชุดทักษะเดียวกันนี้มีอยู่ใน [skills.sh](https://skills.sh/orkas-ai/orkas-videostudio) ด้วย จึงติดตั้งด้วย `npx skills add orkas-ai/orkas-videostudio` ได้เช่นกัน ทักษะเหล่านี้เรียกใช้ CLI `ovs` จึงต้องติดตั้ง CLI ก่อนตามที่อธิบายไว้ด้านบน

**2) เครื่องมือ MCP** ลงทะเบียนเซิร์ฟเวอร์:

```bash
claude mcp add ovs -- node /path/to/Orkas-VideoStudio/packages/mcp/dist/index.js   # Claude Code
codex  mcp add ovs -- node /path/to/Orkas-VideoStudio/packages/mcp/dist/index.js   # Codex
```

**3) CLI ที่อธิบายตัวเองได้ (เอเจนต์ใดก็ได้ที่มีเชลล์)** ไม่ต้องใช้ตัวโหลด:

```bash
ovs skills               # list the skills
ovs skill video-studio   # print the entry skill into context
ovs --help               # the full command surface
```

จากนั้นแค่ขอวิดีโอจากเอเจนต์ของคุณ เอเจนต์จะอ่าน `video-studio` ก่อน แล้วโหลดเอกสารอ้างอิงด้านขั้นตอนและงานฝีมือที่ต้องใช้

## โปรดักชันทำงานอย่างไร

เอเจนต์จะตั้งชื่อโฟลเดอร์สั้น ๆ และเก็บทุกอย่างไว้ในนั้น:

```text
lamp-ad/
  assets.json            every file the video uses: id, kind, path, origin (upload / page / generated / edited)
  product.json           sourced facts such as price and specs, referenced from scenes by id
  media/                 imported and generated files
  videos/main/
    manifest.json        the scene timeline: scenes, clips, text, narration, music tracks, captions
    index.html           optional designed page for text and motion
```

ลำดับฉากคือลำดับการเล่น เวลาเริ่มต้นและความยาวทั้งหมดคำนวณจากฉากและไม่ถูกจัดเก็บไว้ การย้ายฉากจึงไม่ทำให้จังหวะเวลาขัดแย้งกัน ราคาจะอยู่ใน `product.json` เพียงที่เดียว และทุกฉากที่แสดงราคาจะอ่านค่าจากที่นั่น สำหรับวิดีโอรูปแบบอื่นที่ทำคู่ขนานกัน เช่น อัตราส่วนภาพอื่น ภาษาอื่น หรือคัต A/B เอเจนต์จะเพิ่ม video id อื่นที่ใช้แอสเซ็ตชุดเดียวกัน ดู[ข้อกำหนดของไทม์ไลน์](packages/skills/video-studio/references/timeline.md)

ตัวอย่างการรันทั่วไป:

```text
ovs timeline import   --production lamp-ad --inputs '["/path/to/lamp.jpg"]'
ovs timeline prepare  --production lamp-ad --video-id main
ovs timeline check    --production lamp-ad --video-id main
ovs timeline snapshot --production lamp-ad --video-id main --out lamp-ad/preview.png
#   the agent inspects every sampled frame and fixes confirmed problems in one batch
ovs timeline render   --production lamp-ad --video-id main --out lamp-ad/render/main.mp4
ovs timeline ship     --production lamp-ad --video-id main --input lamp-ad/render/main.mp4
```

`ship` จะวัดไฟล์สุดท้ายก่อนบันทึก ได้แก่ ความยาว ขนาดแคนวาส เสียง ความดังเสียง และความครอบคลุมของเสียงบรรยาย คำเตือนเรื่องคำบรรยายใต้ภาพจะถูกทำเครื่องหมายไว้ให้ยืนยันด้วยตา และจะส่งคืนเฟรมจาก MP4 จริง การส่งมอบแต่ละครั้งจะกลายเป็นเวอร์ชันที่แก้ไขไม่ได้ ไฟล์ที่เรนเดอร์ก่อนการเปลี่ยนแปลงล่าสุดจะถูกปฏิเสธเพราะล้าสมัย และการส่งมอบก่อนหน้าจะไม่ถูกเขียนทับเด็ดขาด การผ่านการตรวจสอบเหล่านี้ไม่ได้รับรองคุณภาพของภาพ การตรวจทานภาพจะนับเป็น `not_checked` จนกว่าจะมีคนดูเฟรมจริง ๆ

เมื่อคุณยอมรับผลตรวจที่ยังเหลืออยู่รายการใดรายการหนึ่งอย่างชัดแจ้ง ให้ส่งโค้ดที่ตรงตัวของรายการนั้นด้วย `--accept-findings '["CODE"]' --accept-reason '<your decision>'` เวอร์ชันนั้นจะบันทึกการตัดสินใจนี้ไว้ และข้อผิดพลาดอื่นทั้งหมดยังคงขวางการส่งมอบ การเขียนจะทำทีละรายการโดยใช้ `.ovs-timeline.lock` หากระบบแครชแล้วไฟล์นี้ค้างอยู่ ให้ยืนยันว่าโปรเซสที่เป็นเจ้าของหยุดทำงานแล้วก่อนลบ [ข้อกำหนดของไทม์ไลน์](packages/skills/video-studio/references/timeline.md) อธิบายทั้งสองเรื่องนี้

**การแก้ไขยังคงประหยัดและทำในเครื่อง** คำ คัต ลำดับ เพลงประกอบ หรือคำบรรยายใต้ภาพที่เปลี่ยนจะแก้ไขในที่เดิม เฉพาะบทพูดที่เปลี่ยนเท่านั้นที่จะพากย์ใหม่ และเฉพาะช็อตที่ผิดเท่านั้นที่จะสร้างใหม่ ภายในวงเงินที่อนุมัติไว้แล้ว การแก้ข้อความคำบรรยายใต้ภาพไม่ได้เปลี่ยนเสียงพูด HyperFrames เรนเดอร์วิดีโอทั้งเรื่องทุกครั้ง บิลด์แบบพกพานี้ไม่แคชฉากที่เรนเดอร์แล้ว

## แคนวาสวิดีโอในเบราว์เซอร์

เมื่อ `timeline import`, `timeline prepare`, `timeline render` หรือ `timeline ship` สำเร็จ (จาก CLI หรือ MCP) OVS จะเปิดแคนวาสของโปรดักชันนั้นในเบราว์เซอร์เริ่มต้นของคุณ คำสั่งถัด ๆ ไปจะใช้แท็บเดิมแทนการเปิดแท็บใหม่ แคนวาสแก้ไขไฟล์ชุดเดียวกับ CLI และ MCP การเปลี่ยนแปลงจึงไหลได้ทั้งสองทาง ขณะที่เอเจนต์กำลังทำงาน แคนวาสจะอยู่ในสถานะดูได้อย่างเดียว

บนแคนวาส คุณสามารถ:

- **ดูและส่งออก** เล่นวิดีโอ สลับระหว่างเวอร์ชันที่ส่งมอบแล้ว และดาวน์โหลดเวอร์ชันที่ต้องการ
- **จัดวางสื่อ** อัปโหลด ลากวาง หรือวางฟุตเทจ จากนั้นย้ายและเชื่อมการ์ดบนบอร์ด
- **แก้ไขฉาก** เปลี่ยนคำ ลำดับ และรูปภาพ รวมถึงเพิ่ม ลบ หรือนำฉากที่ลบไปกลับมาใส่
- **สร้างและทำช็อตใหม่** สร้างช็อตภาพหรือวิดีโอใหม่จากการ์ด หรือสร้างช็อตที่มีอยู่ใหม่อีกครั้ง คุณเลือกภาพอ้างอิงหรือเฟรมแรกและเฟรมสุดท้าย รวมถึงโมเดล ความละเอียด และเสียงได้ ตัวเลือกที่โมเดลรองรับไม่ได้จะถูกปิดไว้ ไล่ดูผลลัพธ์ก่อนหน้าและเลือกอันที่จะใช้ แคนวาสจะถามก่อนทุกคำขอที่มีค่าใช้จ่าย
- **อัปเดตวิดีโอ** การแก้ไขฉากทั่วไปจะเรนเดอร์และส่งมอบภายในเครื่อง โดยแสดงความคืบหน้าบนการ์ดวิดีโอ การเปลี่ยนข้อเท็จจริงของสินค้า บรรทัดเสียงบรรยาย หรือเสียงผู้พูดที่ใช้ทั้งวิดีโอ จะสร้างคำขอส่งให้เอเจนต์ของคุณ เพราะการแก้ไขเหล่านั้นต้องใช้วิจารณญาณของเอเจนต์ หากการตรวจสอบก่อนส่งมอบหยุดการอัปเดตเพราะฉากมีภาพนิ่งที่ไม่เคลื่อนไหว การ์ดวิดีโอจะมีตัวเลือก **Preview this version** (ดูตัวอย่างเวอร์ชันนี้) **Return to editing** (กลับไปแก้ไข) หรือ **Update anyway** (อัปเดตต่อ) ตัวเลือก Update anyway จะเก็บไฟล์ที่เรนเดอร์นั้นไว้โดยไม่เรนเดอร์ใหม่
- **บอกเอเจนต์** เขียนคำขอสั้น ๆ เกี่ยวกับฉาก ช็อต การ์ดฟุตเทจ หรือวิดีโอ คำขอจะถูกส่งไปพร้อมบริบทของการ์ดนั้น

แคนวาสจะเปิดเป็นภาษาจีน ปุ่มภาษาของแคนวาสใช้สลับระหว่างภาษาจีนกับภาษาอังกฤษ และจะจำภาษาที่คุณเลือกไว้

### ส่งคำขอกลับไปยังเอเจนต์ของคุณ

ปุ่ม **Send** จะส่งไปยังบทสนทนาที่สร้างโปรดักชันนั้นเท่านั้น หากบทสนทนานั้นรับคำขอไม่ได้ ฉบับร่างจะยังอยู่บนแคนวาส ไม่มีการคัดลอกสิ่งใดไปยังคลิปบอร์ด ไม่มีการส่งซ้ำอัตโนมัติ และไม่มีการส่งไปยังเซสชันใหม่ การแก้ไข การอัปเดต และการส่งออกยังทำงานได้แม้ไม่มีเอเจนต์เชื่อมต่ออยู่

- **Codex** เมื่อ `ovs` รันอยู่ในเธรดของ Codex คำขอจะถูกเข้าคิวในเธรดเดียวกันนั้น ต้องใช้ Codex CLI 0.160.1 ขึ้นไป และต้องให้ app server ภายในเครื่องของ Codex ทำงานอยู่ เธรดที่ปิดไปแล้วหรือยังไม่ได้โหลดจะแสดงเป็นใช้งานไม่ได้
- **Claude Code** คำขอจะเข้ามาผ่านช่องทาง MCP (channel) ซึ่งเป็นฟีเจอร์ research preview ของ Claude Code การเชื่อมต่อ MCP ธรรมดาไม่เพียงพอ ลงทะเบียนเซิร์ฟเวอร์ด้วย `--claude-channel` แล้วเริ่ม Claude Code โดยเปิดใช้ช่องทางนั้น:

  ```bash
  claude mcp add ovs -- node /path/to/Orkas-VideoStudio/packages/mcp/dist/index.js --claude-channel
  claude --dangerously-load-development-channels server:ovs
  ```

  สร้างวิดีโอผ่านเครื่องมือ MCP ของ `ovs` เพื่อให้แคนวาสเปิดขึ้นโดยผูกกับช่องทางนั้น แคนวาสที่เปิดจาก CLI ในเชลล์จะติดต่อ Claude Code ไม่ได้ Claude Code จะแสดงคำเตือนเรื่องการพัฒนาภายในเครื่อง (local development) ตอนเริ่มต้น ช่องทางต้องใช้การลงชื่อเข้าใช้ claude.ai หรือคีย์ API ของ Console และในแผน Team และ Enterprise ผู้ดูแลระบบต้องเปิดใช้ก่อน ดู[ช่องทางของ Claude Code](https://code.claude.com/docs/en/channels)

### เปิดโปรดักชันด้วยตัวเอง

```bash
ovs studio --production ./lamp-ad                   # canvas only
ovs studio --production ./lamp-ad --agent codex     # canvas with its own Codex session
ovs studio --production ./lamp-ad --agent claude    # canvas with its own Claude Code session
```

ให้คำสั่งทำงานค้างไว้ขณะใช้แคนวาส เมื่อใช้ `--agent` แคนวาสจะรันเซสชันแบบเนทีฟในโฟลเดอร์โปรดักชัน ซึ่งใช้การลงชื่อเข้าใช้ โมเดล และการตั้งค่าสิทธิ์ของ CLI คุณเอง เซสชันนั้นต้องใช้ Codex 0.160.1+ หรือ Claude Code 2.1.148+ คำขอสิทธิ์และคำถามของเซสชันจะแสดงบนแคนวาส แคนวาสจะกู้คืนเซสชันที่บันทึกไว้ของโฟลเดอร์นั้น เว้นแต่คุณจะส่ง `--resume <session-id>` เพื่อส่งต่อเซสชันที่ระบุ หรือ `--new-session` เพื่อเริ่มใหม่ ตัวเลือกอื่น ๆ:

- `--no-open` พิมพ์ลิงก์เข้าถึงโดยไม่เปิดเบราว์เซอร์
- `--port` เลือกพอร์ต loopback
- `--recover` เรียกคืนแคนวาสที่เจ้าของเดิมออกไปแล้ว

หากต้องการปิดการเปิดแคนวาสอัตโนมัติระหว่างทำงานโปรดักชัน ให้ตั้งค่า `OVS_STUDIO_AUTO_OPEN=0` ซึ่งปิดไว้อยู่แล้วใน CI

## ใช้ผู้ให้บริการสร้างสื่อของคุณเอง

ตั้งค่าผู้ให้บริการใน `~/.config/orkas-video-studio/config.json` (หรือ `$OVS_CONFIG_DIR/config.json`) หรือด้วยตัวแปรสภาพแวดล้อม ตัวแปรสภาพแวดล้อมจะมีผลเหนือไฟล์

```json
{
  "tts":   { "provider": "openai", "api_key": "…", "model": "gpt-4o-mini-tts", "voice": "…" },
  "image": { "provider": "gemini", "api_key": "…" },
  "video": { "provider": "kling", "api_key": "…", "model": "…" }
}
```

| ความสามารถ | ค่า `provider` | ตัวแปรสภาพแวดล้อม |
|---|---|---|
| เสียงพูด (`ovs speak`) | `openai`, `openai-compatible`, `doubao`, `minimax`, `aliyun` (Qwen / CosyVoice), `google`, `elevenlabs` | `OVS_TTS_PROVIDER` · `_BASE_URL` · `_API_KEY` · `_MODEL` · `_VOICE` · `_FORMAT` · `_PROXY_URL` |
| ภาพ (`ovs image`) | `openai` (เอนด์พอยต์ใดก็ได้ที่เข้ากันได้กับ OpenAI รวมถึง Seedream), `gemini` | `OVS_IMAGE_PROVIDER` · `_BASE_URL` · `_API_KEY` · `_MODEL` |
| วิดีโอ (`ovs video`) | `doubao` (Seedance), `minimax`, `vidu`, `kling`, `google` (Veo), `google-cloud` (Veo), `runway`, `aliyun` (Wan), `atlas`, `muapi` | `OVS_VIDEO_PROVIDER` · `_BASE_URL` · `_API_KEY` · `_MODEL` |

คุณตรวจสอบการตั้งค่าได้โดยไม่ต้องเรียกใช้บริการที่มีค่าใช้จ่ายใด ๆ:

```bash
ovs speech-capabilities                                    # resolved voice/model/language profile, no secrets printed
ovs video-models                                           # what the configured video model supports
ovs video-params --request '{"duration":5,"ratio":"9:16"}' # what that request would actually send
```

รัน `ovs narration fit` ทั้งก่อนและหลังสังเคราะห์เสียง เพื่อให้เสียงบรรยายแต่ละบรรทัดอยู่ภายในช่วงเวลาของฉากหรือของแผน การสร้างวิดีโอรับภาพอ้างอิง อัตราส่วนภาพ ความยาว ความละเอียด และแฟล็กเสียงที่ระบุชัดเจน การเรียกผู้ให้บริการจึงตรงกับแผนที่อนุมัติ สำหรับโปรเจกต์ `plan.json` คำสั่ง `ovs plan validate` ยังตรวจอัตราส่วนภาพ ความยาว และการดำเนินการของแต่ละเซกเมนต์ที่ต้องสร้าง เทียบกับ `video.provider` ที่ตั้งค่าไว้ ก่อนจะสร้างสิ่งใด

ผู้ให้บริการบางรายต้องตั้งค่าเพิ่มอีกเล็กน้อย:

- **Google Cloud Veo** ใช้ `video.workspace_id`, `video.region` และโทเคน API หรือ JSON ของบัญชีบริการ (service account) ใน `video.api_key`
- **Alibaba** ฝั่งเสียงพูดใช้เอนด์พอยต์ของ workspace ใน `tts.base_url` ส่วนวิดีโอ Wan ต้องใช้ `video.workspace_id` และ `video.region`
- **เสียงที่ใช้ได้เฉพาะแบบโคลน** ต้องใช้ voice id ที่คุณลงทะเบียนไว้กับผู้ให้บริการ
- **เสียงพูดผ่าน WebSocket** จะส่งผ่าน `tts.proxy_url` เฉพาะเมื่อคุณตั้งค่าไว้เท่านั้น
- **ภาพหรือวิดีโออ้างอิง** ส่งเป็น URL สาธารณะของภาพหรือวิดีโอ จำนวนที่รองรับและการรองรับเฟรมแรก/เฟรมสุดท้ายแตกต่างกันไปตามโมเดล
- **[MuAPI](https://muapi.ai)** ต้องเลือกอย่างชัดเจนด้วย `video.provider: "muapi"` เมื่อเลือกแล้ว `MUAPI_API_KEY` จะมีลำดับความสำคัญเหนือ `OVS_VIDEO_API_KEY` แต่คีย์เพียงอย่างเดียวจะไม่ทำให้เลือก MuAPI เด็ดขาด `video.model` / `OVS_VIDEO_MODEL` รองรับเอนด์พอยต์ Kling v2.1 ที่ผ่านการตรวจสอบแล้ว ได้แก่ `kling-v2.1-master-t2v`, `kling-v2.1-master-i2v`, `kling-v2.1-standard-i2v` และ `kling-v2.1-pro-i2v` ส่วน slug อื่นจะถูกปฏิเสธแทนที่จะส่งไปพร้อมเนื้อหาคำขอที่ไม่ตรงกัน ค่าเริ่มต้นของการสร้างวิดีโอจากข้อความคือ `kling-v2.1-master-t2v` และเมื่อมี `image_url` เป็นเฟรมแรก ค่าเริ่มต้นคือ `kling-v2.1-master-i2v` ความยาวเป็น 5 หรือ 10 วินาที และอัตราส่วนภาพเป็น `16:9`, `9:16` หรือ `1:1` อินพุต `resolution`, `generate_audio` และ `quality` ที่ไม่ผูกกับผู้ให้บริการรายใดยังเข้ากันได้กับแผนที่ลงนามแล้ว โดย Kling จะไม่ใช้ค่าความละเอียดและเสียง ส่วนคุณภาพจะถูกตรวจสอบแต่ไม่ถูกส่งไป ตัวควบคุมการแก้ไขและภาพอ้างอิงเพิ่มเติมจะถูกปฏิเสธจนกว่าจะรองรับสคีมา MuAPI ที่ตรงกัน base URL เริ่มต้นมี `/api/v1` อยู่แล้ว และ base URL ที่กำหนดเองก็ต้องมีเช่นกัน ดูสัญญาแบบส่งงานแล้วโพลผล (submit-and-poll) และพารามิเตอร์เฉพาะของแต่ละโมเดลได้ที่[เอกสารอ้างอิง API ของ MuAPI](https://muapi.ai/docs/api-reference)

แคตตาล็อกโมเดลของผู้ให้บริการอธิบายสัญญา API ของผู้ให้บริการแต่ละราย แต่ไม่ได้รับประกันว่าใช้งานได้จริงในขณะนั้นหรือราคาปัจจุบัน

## อะไรช่วยคุมการสร้างสื่อให้อยู่ในขอบเขต

เอเจนต์จะใช้สื่อที่คุณมีอยู่แล้วทุกครั้งที่ใช้กับช็อตนั้นได้ และสร้างเฉพาะสิ่งที่ขาด การตั้งค่าข้อมูลรับรองไว้ไม่ถือเป็นการอนุมัติให้ใช้จ่าย ก่อนทำงานที่มีค่าใช้จ่ายใด ๆ เอเจนต์จะยืนยันผู้ให้บริการ โมเดล วัตถุประสงค์ จำนวนคำขอรวมการลองใหม่ และค่าใช้จ่ายโดยประมาณ แล้วทำตามขอบเขตนั้น การปฏิเสธจะหยุดการเรียกใช้ที่มีค่าใช้จ่ายสำหรับคำขอนั้น และช็อตที่ไม่ดีจะแก้ใหม่ได้ไม่เกินสองเทค ก่อนที่เอเจนต์จะขอให้คุณเปลี่ยนแนวทาง

คำขอที่มีค่าใช้จ่ายแต่ละรายการจะเก็บใบเสร็จ (receipt) ไว้ข้างผลลัพธ์ งานวิดีโอที่ไม่ทราบว่าจบลงอย่างไรจะบล็อกการส่งงานใหม่ไปยังผลลัพธ์เดียวกันจนกว่าคุณจะตรวจสอบ และจะไม่ถูกส่งซ้ำอัตโนมัติเด็ดขาด ดู[สิทธิ์ในการสร้างสื่อ](packages/skills/video-studio/references/generation.md)

`ovs speak` จะเขียนใบเสร็จของคำขอและของเสียงไว้ข้างผลลัพธ์ และจะใช้ซ้ำเฉพาะคำขอที่ตรงกันทุกประการและไบต์ของเสียงยังสมบูรณ์เท่านั้น ดังนั้นให้ส่ง `--language` เสียง โมเดล ความเร็ว และฟอร์แมตที่อนุมัติแล้ว การเปลี่ยนค่าใดค่าหนึ่งจะทำให้ใช้ซ้ำไม่ได้ คำสั่งนี้ยังจองผลลัพธ์ไว้ก่อนส่งคำขอ ซึ่งป้องกันการเรียกซ้ำที่เกิดพร้อมกัน

ไม่มีบริการเพลงที่โฮสต์ไว้ เพลงมาจากไฟล์ที่มีสิทธิ์ใช้งานซึ่งคุณจัดหามาเอง และเอเจนต์จะบันทึกแหล่งที่มาและสัญญาอนุญาตของแต่ละไฟล์

## ข้อมูลอ้างอิงคำสั่ง

รัน `ovs <command> --help` เพื่อดูอินพุตแบบมีชนิดข้อมูลของแต่ละคำสั่ง เครื่องมือ MCP ใช้ชื่อเดียวกันแต่ใช้ขีดล่าง เช่น `timeline_prepare` และ `edit_trim_silence`

| หมวด | คำสั่ง |
|---|---|
| การตั้งค่า | `doctor`, `skills [--install]`, `skill <name>` |
| โปรดักชัน | `timeline import · prepare · status · check · snapshot · render · ship`, `studio` |
| ตัดต่อ (ffmpeg) | `edit probe · trim · concat · reframe · burnsubs · overlay · extract-frame · loudness · normalize-loudness · mix · select · trim-silence · remove-fillers` |
| วิเคราะห์ | `transcribe`, `phrases`, `silence`, `scenes`, `quality`, `beats`, `activity` |
| เสียงบรรยาย | `narration timing · fit`, `speech-capabilities`, `speak` |
| การสร้างสื่อ | `image`, `image-prepare`, `video`, `video-models`, `video-params` |
| โปรเจกต์รุ่นก่อน | `composition prepare · reconcile`, `plan validate · summarize · promise-check · rank-takes`, `draft`, `render`, `lint`, `check`, `snapshot`, `gate transition`, `inspect` (ชื่อแทนของ `check`) |

โปรเจกต์ที่สร้างด้วยฟอร์แมต EDL `plan.json` และ `composition-manifest.json` แบบเดิมยังใช้งานได้ผ่านคำสั่งในหมวด "โปรเจกต์รุ่นก่อน" งานใหม่ใช้ไทม์ไลน์ฉาก สำหรับ `plan.json` ที่ประกอบเสร็จแล้ว ให้ตรวจสอบทั้งไฟล์ที่เสร็จแล้วและฟุตเทจที่เป็นส่วนประกอบ:

```bash
ovs plan promise-check project/plan.json --probe-produced --video project/render/video.mp4
```

เครื่องมือ MCP ที่เทียบเท่ากันคือ `plan_promise_check` ซึ่งรับ `probe_produced` และ `video` โดยจะวัดความยาว ขนาดแคนวาส เสียง ความดังเสียงแบบ integrated และช่วงที่มีเสียงพูดของแต่ละบรรทัด หากไม่มีหลักฐานของเสียงบรรยาย การตรวจจะไม่ผ่าน และเมื่อฝังซับไตเติลลงในภาพ คำเตือนเรื่องคำบรรยายใต้ภาพต้องตรวจด้วยตา

## คำถามที่พบบ่อย

### Claude Code ทำวิดีโอได้ไหม?

ได้ เมื่อติดตั้ง OrkasVideoStudio แล้ว Claude Code จะอ่านทักษะ `video-studio` และใช้ CLI `ovs` หรือเครื่องมือ MCP เพื่อตัดต่อฟุตเทจ สร้างโมชันกราฟิก ใส่เสียงบรรยายและคำบรรยายใต้ภาพ และเรนเดอร์ MP4 ที่ผ่านการตรวจสอบแล้วบนเครื่องของคุณ Codex, Cursor และเอเจนต์อื่นใดที่รันเชลล์หรือรองรับ MCP ได้ก็ทำงานแบบเดียวกัน ดู[สั่งงานจาก Claude Code, Codex หรือเอเจนต์เขียนโค้ดตัวใดก็ได้](#สั่งงานจาก-claude-code-codex-หรือเอเจนต์เขียนโค้ดตัวใดก็ได้)

### ใช้ฟรีไหม และต้องมีคีย์ API หรือเปล่า?

OrkasVideoStudio ใช้ได้ฟรีและใช้สัญญาอนุญาต MIT การตัดต่อ โมชันกราฟิกที่ออกแบบไว้ คำบรรยายใต้ภาพ และการถอดเสียงเป็นข้อความทำงานภายในเครื่องและไม่ต้องใช้คีย์ API การสร้างภาพ คลิปวิดีโอ หรือเสียงพูดเป็นตัวเลือกเสริมและใช้บัญชีผู้ให้บริการของคุณเอง ซึ่งเรียกเก็บเงินจากคุณโดยตรง ก่อนการเรียกใช้ที่มีค่าใช้จ่ายใด ๆ เอเจนต์จะยืนยันผู้ให้บริการ โมเดล จำนวนคำขอ และค่าใช้จ่ายโดยประมาณกับคุณ ดู[อะไรช่วยคุมการสร้างสื่อให้อยู่ในขอบเขต](#อะไรช่วยคุมการสร้างสื่อให้อยู่ในขอบเขต)

### เป็นทางเลือกโอเพนซอร์สแทน Claude Motion, CapCut และ Higgsfield ใช่ไหม?

ใช่ เช่นเดียวกับ Claude Motion ตรงที่ให้ Claude Code เขียนโมชันกราฟิกเป็นโค้ด แต่ใช้ได้กับ Claude Code บน Pro, Max, Ultra หรือคีย์ API ไม่ใช่เฉพาะในแผน Team และ Enterprise และยังใช้กับเอเจนต์อื่นได้ด้วย ต่างจาก CapCut ตรงที่เอเจนต์ของคุณเป็นผู้ตัดต่อตามคำอธิบายของคุณ แทนที่คุณจะต้องตัดเองด้วยมือบนไทม์ไลน์ ต่างจาก Higgsfield ตรงที่ไม่ได้โฮสต์โมเดลหรือขายเครดิต: เอเจนต์ของคุณเรียกใช้ Seedance, Kling, Veo และโมเดลวิดีโออื่น ๆ ด้วยคีย์ของคุณเอง แล้วนำช็อตมารวมกับฟุตเทจ โมชันกราฟิก เสียงบรรยาย และคำบรรยายใต้ภาพของคุณ ดู[เปรียบเทียบกับเครื่องมืออื่น](#เปรียบเทียบกับเครื่องมืออื่น)

### ตัดต่อฟุตเทจที่มีอยู่แล้วได้ไหม?

ได้ ตัดช่วงและต่อคลิป ปรับเฟรมเป็น 9:16, 1:1 หรือ 16:9 ตัดช่วงเงียบและคำเติมออก ตัดตามจังหวะบีต ฝังคำบรรยายใต้ภาพ และปรับความดังเสียงให้สม่ำเสมอ ฟุตเทจของคุณอยู่ในไทม์ไลน์เดียวกับโมชันกราฟิกและช็อตที่สร้างขึ้น

### ใช้โมเดลวิดีโอ ภาพ และเสียงพูดตัวไหนได้บ้าง?

สำหรับวิดีโอ: Seedance, Kling, Veo (ผ่าน Google หรือ Google Cloud), Runway, Wan, MiniMax และ Vidu รวมถึง Atlas และ MuAPI สำหรับภาพ: Gemini และ OpenAI หรือเอนด์พอยต์ใดก็ได้ที่เข้ากันได้กับ OpenAI รวมถึง Seedream สำหรับเสียงพูด: OpenAI, Doubao, MiniMax, Alibaba (Qwen และ CosyVoice), Google, ElevenLabs และเอนด์พอยต์ที่เข้ากันได้กับ OpenAI ทั้งหมดนี้ทำงานด้วยคีย์ของคุณเอง ดู[ใช้ผู้ให้บริการสร้างสื่อของคุณเอง](#ใช้ผู้ให้บริการสร้างสื่อของคุณเอง)

### ติดตั้งอย่างไร?

ติดตั้งจากซอร์สโค้ด: โคลนรีโพ รัน `pnpm install && pnpm build` แล้วตรวจสอบการตั้งค่าด้วย `ovs doctor` คุณต้องมี Node 22 ขึ้นไป, pnpm, ffmpeg และ ffprobe แพ็กเกจ npm ยังไม่ได้เผยแพร่ ดู[การติดตั้ง](#การติดตั้ง)

- **ภายใน Orkas** มาเป็น[เอเจนต์ในตัว](https://orkas.ai/agents/video-studio/?source=gh-orkas-vs) โดยไม่ต้องติดตั้งแยก คุณแชตกับเอเจนต์ในแอปเดสก์ท็อปแทนเทอร์มินัล และการสร้างสื่อทำงานบนโมเดลในตัวของ Orkas (บัญชีใหม่รับฟรี 500 เครดิต) หรือบนคีย์ของคุณเองได้ [ดาวน์โหลด Orkas](https://orkas.ai/download/?source=gh-orkas-vs) สำหรับ macOS หรือ Windows

## การพัฒนา

```bash
pnpm install
pnpm build            # tsc per package (core → tools → cli / mcp)
pnpm typecheck
pnpm test             # vitest
pnpm benchmark        # zero-key core correctness + throughput floors
pnpm test:video       # mock provider round-trip → real playable MP4 → ffprobe
pnpm test:video:e2e   # real three-scene production through the built CLI, plus CLI/MCP smoke
pnpm verify           # everything above; also the CI entry point
```

`pnpm install` จะใช้แพตช์ HyperFrames ที่มีเวอร์ชันกำกับใน [`patches/`](./patches/) ซึ่งทำให้เอาต์พุต SDR H.264/H.265 ใช้เมทริกซ์ BT.709 ตามที่เมทาดาทาของไฟล์ระบุ ส่วน `OVS_HYPERFRAMES_BIN` ภายนอก หรือทางสำรอง `npx` เพื่อความเข้ากันได้จะไม่ได้รับแพตช์นี้ รันไทม์นั้นจึงต้องมีการแก้สีที่เทียบเท่ากันอยู่แล้ว แพตช์นี้ยังรักษาตราประทับเวลาระดับคำของ Whisper สำหรับภาษาจีนและภาษาญี่ปุ่นด้วย รันไทม์ภายนอกต้องรองรับคุณสมบัตินี้เช่นกัน

`test:video` ไม่ใช้เครดิตของผู้ให้บริการเลย เอนด์พอยต์ Seedance จำลองภายในเครื่องจะส่งคืนไฟล์ทดสอบ H.264 จริง ซึ่ง OVS จะดาวน์โหลดและตรวจสอบด้วย `ffprobe`

`test:video:e2e` ครอบคลุมเส้นทางโปรดักชันทั้งสองแบบผ่าน CLI ที่บิลด์แล้ว:

- **เส้นทาง composition แบบเดิม** สร้างโปรดักชัน 1080p ยาวเก้าวินาที สามฉาก ด้วย composition prepare/reconcile, snapshot, draft gate แบบเต็ม การฝังซับไตเติล และการตรวจ promise ของไฟล์สุดท้าย ถอดรหัส MP4 ทั้งไฟล์ และตรวจลำดับฉาก การเคลื่อนไหวที่มองเห็นได้ เสียงที่ได้ยินในทุกฉาก และพิกเซลของซับไตเติลที่ฝังไว้ รวมถึงตรวจว่าความยาวการส่งมอบที่ผิดจะถูกปฏิเสธ
- **ไทม์ไลน์ฉากปัจจุบัน** เรนเดอร์ไทม์ไลน์สามฉากผ่านเส้นทาง check และ snapshot ของ HyperFrames จริง ตรวจสีของฉาก การเคลื่อนไหวที่เขียนไว้ การเคลื่อนไหวของวิดีโอต้นทางที่ถอดรหัสแล้ว พิกเซลของคำบรรยายใต้ภาพ เสียง การส่งมอบที่แก้ไขไม่ได้ และการปฏิเสธไฟล์เรนเดอร์ที่ล้าสมัย

นอกจากนี้ยังทดสอบส่วนติดต่อ CLI และ MCP ที่บิลด์แล้วด้วย เมื่อไม่มีรันไทม์ที่จำเป็น คำสั่งวิดีโอทั้งสองจะล้มเหลวพร้อมข้อความผิดพลาดที่บอกวิธีแก้ ชุดทดสอบปกติอาจข้ามเคสที่ต้องใช้รันไทม์หนัก ๆ บนเครื่องที่ไม่มี ffmpeg หรือเบราว์เซอร์

`pnpm verify` ต้องผ่านบนโค้ดฉบับสุดท้ายที่จะส่ง ก่อนทุก Git commit หรือ PR คำสั่งนี้รวมเคสโปรดักชันจริงและเป็นจุดเริ่มต้นของ CI ด้วย การเปลี่ยนแปลงที่แก้เฉพาะเทสต์ก็ต้องทำตามกฎเดียวกัน สำหรับการตรวจทานการซิงก์หรือการออกรุ่น ให้เก็บและตรวจดูวิดีโอที่สร้างขึ้น พรีวิว เฟรมสุดท้าย และรายงาน:

```bash
OVS_VIDEO_EVIDENCE_DIR=../Orkas-VideoStudio-artifacts pnpm test:video:e2e
```

ไดเรกทอรีหลักฐานเป็นตัวเลือกที่ต้องเปิดใช้เอง และการรันแต่ละครั้งใช้ไดเรกทอรีย่อยของตัวเอง การรัน CI ปกติจะล้างสื่อชั่วคราวของตัวเอง ไฟล์ทดสอบใช้ HTML/SVG ต้นฉบับและเสียงดนตรีบรรเลงที่สร้างขึ้นภายในเครื่อง ไม่มีการเรียกผู้ให้บริการที่มีค่าใช้จ่าย และไม่ได้อ้างว่าครอบคลุมคุณภาพของ TTS หรือของโมเดล

`pnpm benchmark` ไม่ต้องใช้คีย์และให้ผลแน่นอน คำสั่งนี้จะบิลด์แพ็กเกจ core ตรวจสอบไฟล์ทดสอบของ benchmark แล้ววัด gate transition การตรวจสอบ EDL และสรุปการส่งมอบ การตรวจสอบ composition-manifest และการประมาณเวลาเสียงบรรยาย แต่ละชุดทดสอบมีเกณฑ์ขั้นต่ำของปริมาณงานที่ตั้งไว้อย่างระมัดระวังโดยเจตนา การถดถอยครั้งใหญ่จึงทำให้ล้มเหลว ขณะที่ความแปรปรวนปกติของเครื่องจะไม่ทำให้ล้มเหลว

ดู[คู่มือการประเมินโมเดลแบบเลือกใช้](./eval/video/README.md)ภาษาอังกฤษสำหรับการตั้งค่า คำสั่ง และการเก็บหลักฐาน
