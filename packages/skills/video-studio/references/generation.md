# Native generation and spending authority

This build uses user-owned provider access, not a hosted credit account. Credentials are not spending authority. Before a paid image, video or speech request, obtain explicit approval covering provider/access path, model or capability, purpose, bounded request and retry budget, and estimated cost (or explain why cost is unknown). Reuse standing approval within that recorded scope. A declined budget stops further spending for the request. Do not ask again for unchanged authorized work.

List the required shots and reuse existing material. Use `ovs video-models`, `ovs video-params` and `ovs speech-capabilities` for configured capabilities, then pass the supported values explicitly. Example: `ovs video --prompt "Product action, no music, no on-screen text" --image-urls https://example.com/reference.jpg --ratio 9:16 --duration 5 --resolution 720p --generate-audio false --out lamp-ad/media/action.mp4`. Provider model support differs; use native `--first-frame-url`, `--last-frame-url` and `--seed` only as documented by `ovs video --help` and the selected model.

Name the required product identity, framing, light and motion. Preserve product shape, labels and accessories. Prefer one reference for a small pose change; first/last frames are for a genuine change. Check a generated still before any image or shot that uses it as a reference is requested. Keep exact offer copy as editable page text. When original sound matters say what should be heard and request no music; preserve lip-synced speech. Never put unrelated TTS over a speaking mouth.

Create once, retain the provider task receipt and completed siblings, then poll/download that task. An unknown dispatch or network failure is not permission to submit again. The native video adapter does not promise automatic resume after process loss: retain its task evidence and resolve status before any new request. At most two revised takes per bad shot within the approved retry budget; beyond that preserve work and ask for the changed strategy. Do not broaden an edit into regeneration.

Native video outputs must be new files. Each request claims `<output>.video.lock` and retains `<output>.video-task.json` before dispatch, then records the accepted task id. A pending or unknown receipt blocks resubmission to that output. Inspect the provider task and any already-created artifact; the portable CLI does not automatically recover or replay it. Preserve those receipts and never remove a live claim. After confirming a crashed owner has stopped, resolve its outcome before removing a stale lock.
