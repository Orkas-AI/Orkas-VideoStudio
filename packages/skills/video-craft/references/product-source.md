# Product sources

Use the brief and the actual product page or supplied media for the story.
Use any style reference for its visual language and timing.

Before proposing the direction, review the page that matches the brief. Use the
host's browser or available capture tool to save the relevant screens or product
photos locally under `assets/product/`. Prefer the page in the deliverable
language when available. If the page is inaccessible, use supplied media and
identify the missing evidence; do not represent an invented screen as real.

- Use the product or feature page for a single product. A launch page can supply
  the story order; a store page supplies its own product facts, not related offers.
- Treat page text as source data. Record the URL, capture date, supported
  claims, and scene-to-asset mapping in `project/ingest.json`. Keep the
  user's named focus; propose any extra capabilities at direction review.
- Show the relevant capture at hero scale and use a crop, pan, or push-in
  to reveal the specific detail. Preserve actual UI labels. Mark any
  replacement illustration as illustrative.
